# MoonLan — дорожная карта

Полный целевой набор функций (аналог LanTopoLog) и версии, в которых они появятся.

- [x] **v0.1** SNMP-опрос коммутаторов, BRIDGE-MIB, автоматическая топология, двухпанельный веб-интерфейс, поиск, демо-режим
- [ ] **v0.2** Ручное редактирование схемы, сохранение раскладки, настраиваемые контекстные меню устройств _(перенесён — сознательно пропущен, будет реализован в одной из следующих версий)_
- [x] **v0.3** Непрерывный Ping-мониторинг, дата/время последнего ответа, автообнаружение новых устройств, журнал новых MAC-адресов, определение IP и имён хостов (ARP/DNS)
- [x] **v0.4** Корректный алгоритм прямых связей (без ложных связей в звезде), LACP-агрегаты (IEEE8023-LAG-MIB), VLAN на портах (PVID и имена), обнаружение неуправляемых коммутаторов _(счётчики ifInErrors/ifOutErrors/ifInDiscards/ifOutDiscards перенесены в v0.5)_
- [x] **v0.5** Тревоги: email, Telegram, Syslog; пороговые значения трафика; мониторинг трафика до порта коммутатора; счётчики ошибок портов (ifInErrors/ifOutErrors/ifInDiscards/ifOutDiscards)
- [x] **v0.5.1** Наблюдаемые хосты (host_down только по отмеченным); тревоги port_hosts_down и lag_degraded; честная скорость деградировавшего LAG; один SnmpEngine на процесс (утечка fd/памяти); фильтр аномальных скоростей счётчиков; пример systemd-юнита
- [x] **v0.5.2** Стабильные субъекты LAG-тревог (по составу членов); санитар зависших тревог; ручное снятие тревоги; лог ресурсов на INFO и в /api/status; подавление флаппинга (FLAPPING-уведомления)
- [x] **v0.5.3** Уникальность IP хостов (ложные port_hosts_down); grace-период для «тихих» хостов (stale на карте); раздел «Вне карты» для устройств из ARP вне портов; отчёт `diag --hosts` о полноте инвентаря; читаемая панель тревог
- [x] **v0.5.4** Разделение ошибок и отбрасываний (port_errors vs port_discards); относительный критерий ошибок по счётчикам пакетов; псевдо-коммутаторы с учётом известных из БД хостов; `diag --port --watch`; подсветка и сортировка в панели портов
- [x] **v0.5.5** Группировка офлайн-устройств в узлы «Офлайн · N»; подсветка подписи выделенного узла
- [x] **v0.5.6** Возврат непрерывной физики и ручная кнопка «Заморозить раскладку»; офлайн-группы всегда показывают свои устройства; аудит конфигурации `diag --config` и сводка в логе при старте
- [x] **v0.5.7** Строгая валидация записей FDB (фантомные MAC); владение IP и освобождение неподтверждённых адресов; пометка случайных MAC; диагностика `diag --host` и `diag --fdb`; чистка невалидных MAC в базе
- [x] **v0.5.8** Подтверждение новых MAC перед выходом на карту; детектор повреждения кадров (port_frame_corruption); размещение устройств, видимых только через магистрали; магистрали определяются структурно, а не по числу MAC на порту
- [x] **v0.6** LLDP: соседи, подтверждение связей и признак источника (`lldp` / `fdb` / `both`), защита от пересылки LLDP-кадров; обнаружение неопрашиваемых мостов за портами доступа (`unmanaged_bridge_detected`); честный статус STP (не рисуем корень по заглушкам выключенного дерева), панель STP, blocking-порты на карте, тревоги `stp_root_changed` / `stp_topology_change` / `stp_fragmented`; тревога `port_flapping` по ifLastChange; обходчик произвольных MIB `diag --walk`
- [x] **v0.6.1** Исправления по итогам боевой сети: падение `build_topology` на портах с несколькими мостами (пустая карта); мостом считается только сосед с capability `bridge`; LAG и «много соседей на порту» больше не читаются как пересылка LLDP; сопоставление локального порта LLDP по убыванию надёжности (`port_matched_by`) и защита от неоднозначных ключей (HPE 1820); схлопывание строк LLDP одного устройства; видимость упавшего скана в шапке
- [x] **v0.6.2** Одно устройство — один узел (мост, чей MAC есть в FDB своего порта, больше не двоится); три категории LLDP-соседей вместо двух, подписи узлов по LLDP и ромб для маршрутизаторов; подписи портов только настоящие (шаблон прошивки отбрасывается); панель портов с закреплённой шапкой и колонкой порта; `uplink_ports` и узел «Внешняя сеть»; тревога по предполагаемому мосту с severity info
- [x] **v0.6.3** Читаемые ссылки в карточках и списки управляющих адресов колонкой; адрес маршрутизатора из `routers:` второй строкой подписи; демо внешней сети на адресах RFC 5737; подсказка о `uplink_ports` для портов, похожих на выход наружу; SQLite в режиме WAL, `MOONLAN_CONFIG` и абсолютные пути конфига и базы в логе старта
- [x] **v0.6.4** `bytes()` на числовых типах pysnmp (OOM в `diag --walk`); откат HC→32 бита по каждой колонке счётчиков; «нет ответа» отличается от нуля в панели, API и тревогах; `diag --port` всегда делает замеры и печатает отчёт по колонкам; офлайн-устройства остаются на запомненном порту, а не уезжают на транк корня; «Внешняя сеть» за мостом; снятие тревог, подавленных конфигом; порт своего маршрутизатора больше не «выход наружу»
- [x] **v0.6.5** Оборванный walk продолжается с места обрыва (`snmp.retries_on_break`); частичный ответ отличается от «нет ответа» в диагностике и логе; недобранные порты дочитываются поштучными GET из 32-битной колонки; колонка пакетов, отвечающая сплошными нулями при живых октетах, читается как незаполненная; дефолты SNMP подняты до `timeout: 5`, `retries: 2`
- [x] **v0.6.6** GET по синтетическому (отрицательному) ifIndex больше не роняет цикл счётчиков всей сети: `expected` только из реальных интерфейсов, `_get`/`_walk` не выпускают исключение наружу, `asyncio.gather(return_exceptions=True)` в скане и цикле счётчиков; офлайн-группы подключаются к мосту или псевдо-коммутатору своего порта, а не к коммутатору
- [x] **v0.6.7** Loop Detection по приватным MIB: профили моделей по `sysObjectID` (встроены DGS-1210-26 Rev.F1, DES-1210-28/ME и DES-3526, свои добавляются в `loop_detection.profiles`); опрос в цикле счётчиков, а не в скане; тревоги `loop_detected` (critical, сырое значение статуса в тексте) и `loop_detection_disabled` (info); правило «норма известна, всё остальное — петля»; модель без профиля честно показывается как «не сообщает по SNMP», а не как «петель нет»; колонка «Петля» в панели портов, красное ребро и обводка узла на карте, `diag --loop`
- [x] **v0.6.8** Опознание модели до чтения её данных: `_get` возвращает `None` на `noSuchObject`/`noSuchInstance`/`endOfMibView` (в SNMPv2c несуществующий объект приходит успешным ответом, из-за чего проба ветки удавалась на любом устройстве и трём коммутаторам приписывалось «LBD выключен»); профили Loop Detection ключуются наблюдёнными `sysObjectID`, а не корнями веток; «неизвестно» больше не печатается как «выключено», а пустая таблица не считается расхождением нумерации; агрегат `dot3adAggPortAttachedAggID`, которого нет в таблице интерфейсов (или в который вошёл весь коммутатор), отбрасывается с WARNING вместо фантомного транка и вечной `lag_degraded`; коммутаторы из `switches:` и `routers:` больше не поднимают `unmanaged_bridge_detected` о самих себе; пустой `sysName` не даёт подпись из IP дважды; `docs/diag/` убран из репозитория, добавлены `diag --anonymize` и обезличенные образцы в `docs/diag_example/`
- [x] **v0.6.9** Устройство, увиденное на аплинке, не находится за ним: в заявке на размещение первым решает направление порта, вторым — глубина (самый глубокий коммутатор перестал забирать всё, что видит со своего аплинка); магистрали корня считаются нисходящими; MAC, все сведения о котором пришли с аплинков, уходит в «Вне карты», а не подвешивается на порт, за которым его точно нет; в карточке написано, почему выбрана именно эта магистраль. Первые тесты на `build_topology`: этот дефект и обе прошлые регрессии правила. Подготовка релиза: `CHANGELOG.md` и `CHANGELOG_RU.md` от v0.5.8, свежие скриншоты с демо-режима
- [x] **v0.6.10** Устройства, видимые только через магистраль, собираются в один узел «За магистралью · N» за кабелем вместо россыпи точек на нём (порог `trunk_group_threshold`, по умолчанию 3); узел не утверждает, что за портом коммутатор, и не подключается к коммутатору, который мы опрашиваем; приблизительная группа имеет приоритет над офлайн-группой того же порта и считает замолчавших внутри себя. Подготовка релиза v0.6
- [x] **v0.6.11** Панель STP после включения RSTP: Bridge ID разбирается по 802.1t (приоритет и расширение врозь), сдвинутая кодировка приоритета распознаётся и исправляется с предупреждением, корни сравниваются по MAC — ложная `stp_fragmented` снята; участие в дереве определяется по принятому чужому корню и по подтверждению соседями, а не только по истории сходимости, и основание вердикта видно в панели и `diag --stp`; коммутатор, отдающий по BRIDGE-MIB одни нули, так и называется; blocking-порт без линка не рисуется заблокированным; общий скелет для всех панелей (шапка и крестик на месте, прокручивается только содержимое); фрагментация объясняется нарезкой VLAN с показом VLAN магистралей у каждого корня
- [x] **v0.6.12** Бюджет времени на опрос одного коммутатора (`snmp.host_budget_seconds`): медленный агент выпадает из этого скана, а не задерживает всю карту, и помечается как не уложившийся, а не как недоступный — `switch_down` по нему не поднимается и не снимается, последнее полное измерение остаётся на карте с датой; свои параметры SNMP на устройство в `switches:` (`community`, `timeout`, `retries`, `retries_on_break`, `host_budget_seconds`) при полной совместимости со старым списком адресов, действующие параметры печатает `diag --config`; OID, отвечающий нулём строк по таймауту `dead_oid_strikes` раз подряд, перестают спрашивать у этого хоста на `dead_oid_cooldown_scans` сканов — с записью в лог на обоих концах паузы и командой `diag --skipped`; LLDP-соседи RouterOS встают на свои порты (chassis id, пришедший текстом, нормализуется в MAC; `lldpRemLocalPortNum` пробуется и как номер порта моста); ход скана виден в шапке и в `/api/status`

- [x] **v0.6.13** Прочерк означает «не измеряли», а не «тихо протухло»: измеренная скорость отдаётся с возрастом и показывается приглушённо, вместо того чтобы исчезнуть, и скрывается только после `stale_rate_hide_minutes`; цикл счётчиков коротко ждёт занятый сканом хост, а бюджет опроса от двух интервалов и выше сообщается при старте и в `diag --config`; сетевое суждение по STP выполняется до сборки карты, поэтому корень, опознанный по подтверждению соседей, обведён на карте, а не только назван в панели; коммутатор, не завершивший полный опрос `stale_switch_scans` сканов подряд, помечается в карточке и поднимает `switch_stale` (не `switch_down`), а `diag --config` печатает измеренную длительность последнего полного опроса; молчание SNMP разбирается на три случая — неверная community, недоступный хост, нереализованный OID, — и молчание всех коммутаторов разом сообщается как одна причина; мост, не называющий корня, не считается ни работающим, ни отдельным деревом: группа `unknown` исчезла вместе с ложной `stp_fragmented`
